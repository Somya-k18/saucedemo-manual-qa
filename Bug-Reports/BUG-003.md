# BUG-003 — Reset App State leaves stale product button state

**Bug ID:** BUG-003

**Module:** Navigation & Session

**Severity:** Medium

**Priority:** Medium

**Status:** Open

**Test Type:** Manual Testing

**Related Test Case:** TC-NAV-006

**Environment:** SauceDemo Web Application

## Title

Reset App State clears cart data but leaves the product button in a stale UI state until page refresh or navigation.

## Preconditions

* User is logged in with a valid account.
* At least one product is available in the catalog.

## Steps to Reproduce

1. Log in to SauceDemo using a valid user account.
2. Add a product to the cart.
3. Verify that the product button changes from **Add to cart** to **Remove**.
4. Open the application menu.
5. Select **Reset App State**.
6. Return to the product catalog without refreshing the page.
7. Observe the cart state and the product button.

## Expected Result

After selecting **Reset App State**, the application should reset the cart data and update the related UI elements immediately and consistently.

The product button should change back to **Add to cart** when the product is no longer in the cart.

## Actual Result

After selecting **Reset App State**:

* The cart is emptied.
* The cart badge is removed.
* The user remains logged in.
* However, the product button continues to display **Remove** even though the product is no longer in the cart.

The button changes back to **Add to cart** only after a page reload or navigation that causes the product catalog to reload.

## Impact

* The UI does not accurately reflect the current application state.
* Users may believe that the product is still present in the cart when it is not.
* The inconsistent button state can cause confusion when interacting with the product.

## Reproducibility

**Reproducible:** Yes

The issue was reproduced after using **Reset App State**.
