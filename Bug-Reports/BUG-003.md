# BUG-003 — Reset App State Leaves Stale Cart and Product Button State

**Bug ID:** BUG-003

**Module:** Navigation & Session

**Severity:** Medium

**Priority:** Medium

**Status:** Open

**Test Type:** Manual Testing

**Related Test Case:** TC-NAV-006

**Environment:** SauceDemo Web Application

## Preconditions

- User is logged in with a valid account.
- At least one product is available in the catalog.

## Steps to Reproduce

### Scenario A: Product button remains in a stale state

1. Log in to SauceDemo using a valid user account.
2. Add a product to the cart.
3. Verify that the product button changes from **Add to cart** to **Remove**.
4. Open the application menu.
5. Select **Reset App State**.
6. Return to the product catalog without refreshing the page.
7. Observe the cart state and the product button.

### Scenario B: Cart item remains visible after reset

1. Log in to SauceDemo using a valid user account.
2. Add a product to the cart.
3. Navigate to the shopping cart.
4. Open the application menu.
5. Select **Reset App State**.
6. Observe the cart badge and the cart contents.

## Expected Result

After selecting **Reset App State**, the application should reset the cart and update all related UI elements immediately and consistently.

- The cart should contain no products.
- The cart badge should reflect an empty cart, with no item count displayed.
- Product buttons should return to **Add to cart** for products no longer in the cart.
- The cart page should no longer display previously added items.

## Actual Result

After selecting **Reset App State**, the following behaviors were observed:

**Scenario A — Product catalog**

- The cart is emptied.
- The cart badge is removed.
- The user remains logged in.
- The product button continues to display **Remove**, even though the product is no longer in the cart.
- The button changes back to **Add to cart** only after a page reload or navigation that causes the product catalog to reload.

**Scenario B — Shopping cart**

- The cart badge disappears.
- The previously added cart item remains visible on the cart page after the reset.

## Impact

- The UI does not consistently reflect the application state after a reset.
- Users may believe that a product remains in the cart when it has been cleared, or may be confused by stale product button states.
- The inconsistent state can reduce user confidence in the reset functionality and cause confusion during subsequent cart interactions.

## Reproducibility

**Reproducible:** Yes

Both behaviors were confirmed during manual testing.
