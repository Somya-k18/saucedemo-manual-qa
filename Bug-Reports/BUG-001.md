# BUG-001 — Session expiration displays raw, page-specific authentication errors

**Bug ID:** BUG-001

**Module:** Navigation & Session

**Severity:** Medium

**Priority:** Medium

**Status:** Open

**Test Type:** Manual Testing

**Related Test Case:** TC-NAV-005

**Environment:** SauceDemo Web Application

## Title

Session expiration displays raw, page-specific authentication errors instead of graceful session handling.

## Preconditions

* User is logged in with a valid account.
* User is accessing an authenticated/protected page.
* Session becomes invalid after a period of inactivity.

## Steps to Reproduce

1. Log in to SauceDemo using a valid user account.
2. Navigate to an authenticated page such as the Products page.
3. Leave the application inactive for a period of time.
4. After the session becomes invalid, attempt to access or continue using the application.
5. Observe the message displayed on the page.
6. Repeat the scenario from different protected pages.

## Expected Result

When the user's session expires, the application should handle the expired session gracefully by redirecting the user to the login page and displaying a clear, user-friendly session-expiration message.

The application should not expose raw, page-specific authentication errors.

## Actual Result

After the session expires, the user is redirected to the login page, but a page-specific authentication error is displayed.

Examples observed:

* `/inventory.html`
  `Epic sadface: You can only access '/inventory.html' when you are logged in.`

* `/cart.html`
  `Epic sadface: You can only access '/cart.html' when you are logged in.`

* `/dynamic-catalog-lazy-load.html`
  `Epic sadface: You can only access '/dynamic-catalog-lazy-load.html' when you are logged in.`

The behavior was reproduced across multiple protected routes, with the error changing according to the page that was being accessed.

## Impact

* Provides a confusing user experience after session expiration.
* Exposes technical/page-specific information that is not useful to an end user.
* Makes the session-expiration behavior appear inconsistent across different pages.

## Reproducibility

**Reproducible:** Yes

The behavior was observed repeatedly after session expiration and across multiple protected routes.
