# BUG-004 — Checkout Accepts Whitespace-Only Required Fields

**Defect ID:** BUG-004  
**Module:** Checkout  
**Severity:** Medium  
**Priority:** Medium  
**Status:** Open  
**Found During:** Phase 3 — Exploratory Testing  
**Test Session:** ET-SESSION-01 — Checks 4 and 6

## Description

The checkout form accepts whitespace-only values in required customer information fields and allows the user to proceed to the Order Overview.

This behavior was reproduced in three scenarios:

- All three required fields contain only whitespace.
- First Name contains a single space while Last Name and Postal Code contain valid values.
- Postal Code contains a single space while First Name and Last Name contain valid values.

The generated order PDF displays blank-looking customer information for fields containing whitespace-only values under the Ship To section.

## Preconditions

- The user is logged in.
- At least one product has been added to the shopping cart.

## Test Scenarios

### Scenario A — All Required Fields Contain Whitespace

**Steps to Reproduce**

1. Log in to the application.
2. Add a product to the shopping cart.
3. Navigate to checkout.
4. Enter whitespace-only values in First Name, Last Name, and Postal Code.
5. Click **Continue**.
6. Observe the result.

**Expected Result**

The application should reject whitespace-only values and display appropriate validation messages for the required fields. The user should remain on the Checkout Information page until valid values are entered.

**Actual Result**

The application accepts the whitespace-only values and allows the user to proceed to the Order Overview.

**Evidence**

`Evidence/BUG-004/BUG-004-01-Order-PDF-All-Whitespace.png`

### Scenario B — First Name Contains a Single Space

**Steps to Reproduce**

1. Navigate to the Checkout Information page.
2. Enter a single space in First Name.
3. Enter `KK` in Last Name.
4. Enter `302005` in Postal Code.
5. Click **Continue**.
6. Observe the Order Overview.
7. Generate the order PDF and inspect the Ship To section.

**Expected Result**

The application should reject the whitespace-only First Name and display an appropriate validation message. The user should not be allowed to proceed until a valid first name is entered.

**Actual Result**

The application accepts the single-space First Name and allows the user to proceed to the Order Overview. The generated order PDF displays the first name as blank-looking information under Ship To, followed by the entered last name and postal code.

**Evidence**

`Evidence/BUG-004/BUG-004-02-Order-PDF-Blank-First-Name.png`

### Scenario C — Postal Code Contains a Single Space

**Steps to Reproduce**

1. Navigate to the Checkout Information page.
2. Enter a valid First Name.
3. Enter a valid Last Name.
4. Enter a single space in Postal Code.
5. Click **Continue**.
6. Observe the Order Overview.
7. Generate the order PDF and inspect the Ship To section.

**Expected Result**

The application should reject the whitespace-only Postal Code and display an appropriate validation message. The user should remain on the Checkout Information page until a valid Postal Code is entered.

**Actual Result**

The application accepts the single-space Postal Code and allows the user to proceed to the Order Overview. The generated order PDF displays the Postal Code as blank-looking information under Ship To.

**Evidence**

- `Evidence/BUG-004/BUG-004-03-Order-PDF-Blank-Postal-Code.png`

## Impact

The application can accept incomplete customer information during checkout and generate order documents with blank-looking First Name or Postal Code entries. This reduces the reliability and completeness of customer information in the checkout workflow and generated order documentation.

## Reproducibility

All three scenarios were reproduced during exploratory testing.

## Notes

This defect was identified through exploratory testing. The observed behavior indicates that required-field validation does not adequately reject whitespace-only input.
